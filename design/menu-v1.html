A mockup to decide before implementing. The eight projects and their sessions are the ones in your workspace. Everything you see here works: hover, open the menus, enter sort mode and move projects around.

The problem, measured

It is not that the buttons are small. It is that a project header piled up four actions into a 293 px row that also has to say a name of 18 characters. Every way of splitting that width is a bad way.

15 × 22 px What the order arrows measure today. A touch guideline asks for 44 px. With a finger it is not that it is hard: it is that you miss.
190 of 176 px What the longest name needs when the project has something waiting for you — 165 of text plus 25 of badge — against what it has left. That is why it breaks exactly when you look at it most.
14px / 400 The size the name renders at today, when its own rule asks for 12px/600. There are two .project-name rules in the CSS and the second carries a font: inherit that stomps the first.
10 of 17 characters What GITHUB-AcmeProperty and GITHUB-AcmePayments share. They differ at the end, which is exactly what a trailing “…” erases.

Where the pixels come from

Two different things, and they are worth keeping apart. The first is an accident: there are two .project-name rules in styles.css and the second carries font: inherit, a shorthand that rewrites size and weight, so the name comes out at 14px/400 when its own rule asks for 12px/600. The second one is a decision: uppercase with tracking is emphasis, and emphasis is paid in width. This table measures itself in your browser on load, with the same engine that later draws the menu; the red bar is the one that does not fit.

Four ways to split the row

All four take the typography change above for granted. What changes between them is where the actions live. Each one is drawn on desktop and on phone, because the split that works with a mouse is not the one that works with a finger.

A · Like VS Code

The actions do not exist until you hover, and then they appear over the end of the name, taking width from nobody.

Desktop · hover a row
Phone

The name uses the whole row while you read, which is 99% of the time.

It is exactly the VS Code gesture: zero new things to learn.

On a phone there is no hover, so a separate path is needed anyway — here, the ⋯.

Four 22 px icons are still four small targets, only hidden.

B · Everything in one menu

The row keeps what you use daily — new task — and the rest goes into a three-dot menu, the same on desktop and on mobile.

Desktop · hit the ⋯
Phone · same menu, 44 px rows

One path for both screens: what you learn sitting down serves you standing up.

The options can be called by their name — “Move up”, not a 9 px arrow.

Reordering costs one menu opening per hop.

Moving a project six places is six menu openings.

C · Sort mode

The row carries nothing about ordering. A switch up top turns the whole menu into a list of big handles, and on exit everything goes back to normal.

Desktop · hit “Reorder”
Phone · 44 px handles

Reordering stops charging rent on a row you look at a hundred times a day.

While the mode is active nothing competes: 44 px handles fit.

It collapses the sessions, so you see all eight projects at once and sort in one go.

It is a new concept: you have to discover the mode exists.

D · B + C proposal

The row carries a name and two buttons. The menu holds the rare stuff, and from the menu you enter sort mode, which is where the order actually gets touched.

Desktop · ⋯ → “Reorder projects”
Phone

Two controls in the row instead of four, and both a real 22 px.

Sorting happens in one pass, with targets a finger actually hits.

Identical on desktop and phone. No feature lives only in hover.

Unfollowing a project goes from one click to two. It is a destructive action: that does not look like a cost to me, it looks like a second question.

What I would implement

  1. Fix the font: inherit that stomps the name's typography. It is not a design change: it is making the design that is already written apply. It gives back 17 px and it is one line of CSS.
  2. Normal case, no tracking. Another 24 px, without removing a single feature. Between the two, the longest name goes from 165 px to 124 and stops sitting on the edge of breaking.
  3. The “something is waiting” badge, out of the name. Today it lives inside it and steals 25 px on exactly the project you want to read. At the end of the row it takes nothing from anyone.
  4. If something still has to be cut, cut through the middle — GITHUB-Acme…SelfServe — because your names differ at the end. With the full name in the title.
  5. The row keeps the name, “new task” and a ⋯. Unfollow goes to the menu, where a destructive action belongs.
  6. The arrows disappear from the row and the order moves into a mode opened from the ⋯: it collapses the sessions, shows all eight projects at once and gives 44 px to each handle.
  7. Drag can be added on top of the mode later without throwing anything away: inside the mode it no longer competes with the list's scroll, which was what made that option expensive.
